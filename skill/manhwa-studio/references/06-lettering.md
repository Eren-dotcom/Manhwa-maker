# 06 — Lettering

Lettering is where AI pipelines break and where amateur webtoons lose readers. The toolkit composites
every character of text — nothing is ever generated by a model.

---

## Why compositing, not generation

Image models cannot spell, cannot kern, cannot wrap a line, and cannot keep type size consistent
between panels. A single misspelled word in a bubble destroys reader trust faster than imperfect art.
So: prompt text *out* of the art, then draw the text with a real font at a known size in a known box.

```json
{ "character": "sera", "text": "One more delivery.", "style": "speech", "anchor": "top-left" }
```

QC `A003` checks that the series negative block actually contains the anti-text terms. Signage,
screens and book spines must be prompted as **blank** — if words are needed on them, that is prop text,
drawn by the letterer.

## Bubble styles

`BUBBLE_STYLES` in `specs.py` — the full vocabulary, from the reference spec.

| Style | Shape / treatment | Use for |
|---|---|---|
| `speech` | white true oval, tapered tail | normal dialogue — the default |
| `shout` | white jagged starburst + tail | yelling; loses power if it is common |
| `thought` | fuzzy cloud outline, 3-dot trail | inner monologue |
| `whisper` | dashed grey outline, smaller type | a small voice, a held breath |
| `narration` | tinted caption box, no tail | narrator voice, letters, time stamps |
| `dark` | inverted: black fill, white type | a line delivered flat and cold, threat |
| `urgent` | cream fill with a red outline | urgency, a command mid-action |
| `recognition` | tinted cream glow | the beat where someone realises something |
| `symbol` | symbol-only bubble (`?`, `!`, `…`) | a beat with no words at all |
| `hesitant` | wobbly, uneven outline | a cut-off or uncertain line |
| `continuing` | linked double ovals | one speaker continuing across a beat |
| `technique` | small dark caption plate, corner-anchored | technique names, system labels |
| `system` | dark HUD plate with a rule line | LitRPG / status windows, quest UI |
| `radio` | dark plate, cyan border | comms, phone calls, off-screen voices |
| `prop` | type drawn **directly on the art**, rotated to the object | labels, signs, screens, props |
| `sfx` | large outlined display type | sound effects — never inside a bubble |

Grey dashed whispers, inverted black, tinted urgent and cloud thought exist so readers can *see* the
register change without reading the words. Use that.

## Three lettering voices

`series.json → voices`, selected per line with `dialogue.voice`:

| Voice | Look | Use for |
|---|---|---|
| `clean_bold` | clean bold face, the default | most dialogue |
| `condensed_block` | condensed block face, tighter | narration, system, crowds, radio |
| `hand_brushed` | brushed face with a deterministic shake and/or motion blur | shouts, panic, a hand-written line |

The shake is seeded, not random, so re-renders are identical. Assign a voice per character at cast
lock and keep it — a voice changing mid-chapter reads as a lettering error.

## Type rules

| Rule | Value |
|---|---|
| Base dialogue size | **40px at the 1080 master** (scales with `--width`) |
| Readability floor | 14px in the master, **≥20px in the export** (QC `R002`) |
| Leading | 116% of font size |
| Words per balloon | **≤20** (`max_words`; refine `D002`) |
| Lines per balloon | **1–2** (QC `R004`) |
| Wrap width | ≤72% of the panel width (780px at 1080) |
| Balloon size | ≤55% of panel area, and never >78% of panel width / 58% of height |
| Bubble padding | ≈ one letter-width all round; text never touches the edge |
| Line breaks | at natural phrase boundaries, never mid-word |
| Casing | sentence case by default; `caps: true` in `series.json` for traditional all-caps |
| Font choice | a comic face (Anime Ace, CC Wild Words, Komika, Bangers) — never Times/Arial/decorative |
| Fonts per series | 2–3: regular, bold, condensed (the third for system/radio) |

Drop fonts in `assets/fonts/` or point `series.json → lettering.fonts` at them. Without them the
toolkit falls back to DejaVu — legible, but generic. **A real comic font is the cheapest upgrade to
perceived quality you can buy.**

## Placement

Two passes:

1. **Ask the model.** Every panel with dialogue gets "leave clean negative space in the X area for a
   speech bubble" added to its prompt, and a `focus_guard` list of what must never be covered.
   Compose the empty space in: upper thirds, clean skies, flat walls — never over faces, blades or
   key clues.
2. **Measure the result.** An edge-energy scan (32×32 grid) scores every candidate position for visual
   busyness; the balloon goes to the calmest legal spot, avoiding balloons already placed. A requested
   `anchor` is honoured unless it would land on detail.

Overrides: `anchor: "top-left"` (or `top-center`, `middle-right`, `bottom-left`, `center`, …),
`anchor: "@0.5,0.22"` for exact panel fractions, or `anchor_lock: true` to force it even over art.
QC `R005` warns when a balloon sits over the upper-middle band where the face usually is.

**Tails** point `up`/`down`/`left`/`right`/`auto`, or at an exact speaker position:

```json
{ "tail": "auto", "tail_to": { "x": 0.42, "y": 0.78 } }
```

Tails stay short (≈2 type-heights) — long spikes read as amateur. For two-hander panels, put the
speaker's tail toward their side of the frame: x at 0.3 vs 0.7 does most of the work of making a
conversation legible.

## Balloons in the gutters

The spec's signature move: a balloon may live **in the gutter between two panels**, with a thin tail
reaching back into the panel toward the speaker.

```json
{ "character": "sera", "text": "He's not following.", "style": "speech", "place": "gutter" }
```

`assemble` **reserves** the gutter height the balloon needs *before* it lays out the strip, so the
balloon always fits and the pacing gap stays deliberate. The tail is drawn from the gutter into the
panel. A gutter balloon with no tail is an error (`R006`) — the reader cannot tell who is speaking.
QC `P005` reports the reserved gutter as a note so you can confirm it was intentional.

## SFX

```json
{ "character": "sfx", "text": "CRASH", "style": "sfx", "anchor": "@0.42,0.38",
  "fx": "violence", "rotation": -9, "size_scale": 1.15 }
```

- **Colour-coded** (`SFX_PALETTE`): `violence` red · `cold` blue motion · `mystery` violet ·
  `impact` black type with a white glow halo · `neutral` white.
- Drawn with an outline **and** a glow halo so it stays readable over any art.
- **Breaks borders on purpose.** `place: "border"` hangs the type over the panel edge;
  `place: "gutter"` lets it sit in the pacing gap. Both are composited on the strip overlay, so the
  type is never confined by the panel rectangle.
- Rotate 5–15° in the direction of the action; one SFX per panel; repeat a word only for deliberate
  repetition (a heartbeat, a repeated impact).
- Length is fine: `KRRRSH` reads as rain, `THUD` as a body. Keep them shoutable in one breath.
- Never put dialogue on the same panel as a full-height SFX.

## Technique captions and prop text

- `style: "technique"` → a compact dark plate in a panel corner with smaller type
  (`ARCHIVE PLAYBACK`), the genre's way of naming a move without a bubble.
- `style: "prop"` + `prop_rect` + `rotation` → type drawn straight onto the art, no bubble and no
  leader line (`JOB 77-C` on a case). This is the *only* way text should ever appear on an object.

## Reading order in a vertical scroll

- **Top-to-bottom, and dead simple.** Readers see roughly one panel at a time; don't make them resolve
  bubble chains.
- Put the first bubble a reader should read highest, then descend.
- **Never stack three or more bubbles vertically** in one panel — split the panel instead. QC warns
  past 3 bubbles in a panel.
- **Don't put dialogue and the panel's key visual in the same region.** The balloon always wins the
  fight for attention; if it covers the reveal, the reveal is wasted.
- **Give the punchline its own panel.** A line alone in a panel lands; the same line crammed beside two
  others doesn't.

## QC codes you will meet

| Code | Meaning |
|---|---|
| `R002` | type renders under 20px in the export |
| `R003` | a balloon covers more than 55% of its panel |
| `R004` | more than 2 lines in one balloon |
| `R005` | balloon over the upper-middle band (probably the face) |
| `R006` | gutter balloon with no tail |
| `D002` | (refine) more than 20 words in one balloon |

## Final checks before upload

1. Read the whole episode at 40% zoom (≈ phone scale). Any line you strain at is too small.
2. Run `manhwa.py sheets <ep>` and read `lettering-qc.png` — balloon rects, tail endpoints, gutter
   balloons, SFX bounds and prop text, all annotated over the strip.
3. Check every balloon can be attributed to a speaker without ambiguity.
4. Punctuation discipline: ellipses for trailing off, em-dashes for cuts, no double punctuation.
5. Consistent casing across the episode, and a consistent size for the same register.
